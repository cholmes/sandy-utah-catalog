# sandy-utah-catalog

A git-backed Portolan catalog mirroring Sandy City, Utah's public geospatial
data. Metadata lives here. Data bytes live on Source Cooperative under
`portolan-mirrors/sandy-utah-catalog`.

## The publish boundary

`catalog/` is the published catalog. Everything in it is published, and
nothing outside it ever is. Do not move a file into `catalog/` to make it
publish, and do not add a path outside `publish_dir` to `tools/publish.py`.
The boundary is the only thing standing between a scratch file and a public
bucket, and it holds because it is structural rather than a list of
exclusions.

## One publisher, not two

This catalog publishes with `tools/publish.py` and `tools/upload_data.py`.
It does **not** use `portolan push`. The two keep incompatible state —
`portolan push` tracks uploads in `versions.json` keyed on sha256, while
`publish.py` is stateless and compares local size and MD5 against the bucket
listing. Mixing them produces uploads that neither tool believes it made.

The `portolan` CLI is still used locally, in the staging tree only, to convert
data and generate STAC. Its output is then ported into `catalog/`.

## Data never enters git

Never commit a GeoParquet, COG, PMTiles, Zarr, or COPC file. If a gate needs
bytes to check, generate them in CI. Git keeps every version of a binary
forever and deleting it later reclaims nothing.

Staging lives at `../sandy-staging/`, outside this repository.

## Tiles are built with tylertoo, not tippecanoe

PMTiles are generated by [tylertoo](https://github.com/geoparquet-io/tylertoo)
from the local `main` build, then registered by `portolan add --pmtiles`,
which skips its own generation when an up-to-date `.pmtiles` sibling already
exists. Two constraints make that work:

- The PMTiles must be the sibling of the GeoParquet with the same stem.
- `tylertoo --layer-name` must equal that stem, because portolan derives the
  generated style's `source-layer` from it.

Record the tylertoo flags and `--report` figures for each collection in that
collection's `AGENTS.md`. A tiling run that is not written down cannot be
reproduced when the source refreshes.

## Projections

Archival GeoParquet stays in the source CRS, **EPSG:3566** (NAD83/HARN Utah
Central, US survey feet). Only the tiling input is reprojected to EPSG:4326,
and that copy is temporary. A consumer who needs native coordinates cannot
recover them from a reprojected file.

This means lengths and areas computed on the published GeoParquet come out in
**US survey feet**, not metres. Say so in every collection's agent guide.

## The conformance allow-list

`ACCEPTED` in `tests/test_conformance.py` ships empty. Never add an entry
without a matching row in `docs/conformance.md` giving the rule, where it
fires, why it is accepted, and the issue tracking its removal.

## Published agent guides

Every claim in a `catalog/**/AGENTS.md` is either quoted from a source or
measured from the data. An invented join key or column name produces a
confident wrong answer that nothing downstream catches.

Sandy City publishes no data dictionary. Where a column's meaning could not be
established, say that it is undocumented rather than guessing. A column
described wrongly is worse than a column left undescribed.

## The links back to this repository

`catalog/catalog.json` carries absolute `vcs` and `issues` links. The
repository sits outside the published catalog, so a relative href would
resolve against the public base URL and point at a bucket path that holds
nothing.
